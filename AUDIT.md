## A. Critical — publishes false or unlawful content

### A1. `/pricing` is a live page of invented prices — OPEN
`content/pricing.md` is untouched Bigspring template content. It renders at
**https://www.kareplusrugby.co.uk/pricing** as three plans:

- "Basic Plan — Best For Small Individuals — £49/month"
- "Professional Plan — £69/month" (marked *recommended*)
- "Business Plan — Best For Large Individuals — £99/month"

Features listed include "Customs Clearance" and "Cloud Service". None of this
relates to care, and the prices are fabricated. This breaks the plan's hard rule
*"Never invent prices"* and is a CAP Code / CQC truthful-marketing risk on a
regulated care site. It is reachable now.

### A2. `/elements` is a live template demo page — OPEN
`content/elements.md` renders a typography demo ("Heading 1"…"Heading 6",
lorem ipsum, sample tables) at **/elements**. Pure template debris, publicly
reachable.

Both A1 and A2 are generated by the `app/[regular]/page.js` catch-all from
`content/*.md`. Neither is in `sitemap.xml` (good) but neither is blocked in
`robots.txt` either, and both are directly linkable.

### A3. `content/faq.md` is lorem ipsum — OPEN
Six questions ("Will updates also be free?", "Any refunds?", "What is a product
key?") with lorem ipsum answers. **Not currently reachable** — `app/faq/page.js`
wins and `RESERVED` in the catch-all excludes the slug — but the file is one
config edit away from being published. Dead, dangerous content.

## B. Personal-data handling — breaks a hard rule

### B1. `/api/messages` writes personal data into the repository — OPEN
`app/api/messages/route.js` writes every contact submission — name, email,
phone, message — to `data/messages.json`, which **is tracked in git**
(`git ls-files` confirms). The plan's hard rule is explicit:

> Never store personal data on the server, in a database, in a log file, or in
> the repository. Forms email their contents and retain nothing.

Mitigating facts: the file is currently `[]` (empty), so **no personal data has
ever been committed**, and the write is wrapped in try/catch as "best effort".
But the code path is live and would write real data on any host with a writable
filesystem. The two sibling routes (`/api/enquiry`, `/api/apply`) already do
this correctly and document why. This one was missed.

`data/jobs.json` is also tracked but holds no personal data — that one is fine.

### B2. Admin area is protected — DONE
`middleware.js` puts `/admin/*`, `GET /api/messages`, `/api/get-started`,
`/api/request-data` and `POST /api/jobs` behind HTTP Basic auth, fails closed
when `ADMIN_PASSWORD` is unset, and uses a constant-time comparison. This
resolves the P0 in `CLAUDE.md` §7. No action.

## D. SEO and metadata

### D1. Legacy `SeoMeta` emits broken og/twitter tags — OPEN
`config/config.json` has `"base_url": "/"`. `layouts/SeoMeta.js` builds:

- `og:url` = `` `${base_url}/${pathname.replace("/","")}` `` → **`//pricing`**
- `og:image` = `` `${base_url}${meta_image}` `` → **`//images/og-default.png`**

A protocol-relative `//pricing` is not a valid canonical URL. This is plan item
2.3 — fixed for the modern pages but **still live** on every page that uses
`SeoMeta`: `/pricing`, `/elements`, `/domiciliary-care-home`, `/how-we-work`,
`/blogs/page/[slug]`, and all `/blogs/*` via `PostSingle`.

Also note `config.json`'s `base_url: "/"` sits awkwardly against `CLAUDE.md`'s
rule that a `base_url` pointing anywhere other than the live domain must never
be committed. `config/site.json` has the correct value; `config.json` is the
stale duplicate.

### D2. Modern metadata is correct — DONE
`app/layout.js` sets `metadataBase`, a title template, OpenGraph with a real
1200×630 image, `locale: en_GB`, and `MedicalBusiness`/`LocalBusiness` JSON-LD
with an `isReal()` guard that strips `[TODO: …]` values rather than publishing
them. Per-page `title`/`description`/`canonical` exist on the modern routes.

### D3. `sitemap.xml` / `robots.txt` — DONE (one gap)
Both are generated from `site.seo.base_url`. The sitemap correctly lists only
real pages and excludes `/pricing` and `/elements`. **Gap:** robots.txt does not
`Disallow` those two, so they remain crawlable. Moot once they are deleted.

### F1. Body text below the 16px floor — OPEN
The plan sets a hard 16px minimum. Present today:

- **`text-[15px]`** — 30 occurrences across 20 files, including `SiteFooter`,
  `Hero`, `ServicesOverview`, `HowItWorks`, and every form
  (`ApplicationForm`, `EnquiryForm`, `MultiStepEnquiry`, `ContactTabs`,
  `FormStatus`). This is used for genuine body copy, not just captions.

  `TestimonialCarousel`, `StickyContactBar`, `app/error.js`, `app/not-found.js`
- **`text-sm` (14px)** — 51 files

`text-[12px]` in `TwSizeIndicator.js` is a dev-only breakpoint badge; ignore.

### F2. Images and alt text — DONE
No raw `<img>` without `alt` anywhere. `next/image` is used throughout, with

### F3. Carousel — DONE
The auto-rotating hero carousel is gone entirely, replaced by a static hero.
`layouts/home/Hero.js` documents the reason (WCAG 2.2.2, and a care-home
manager landing on a home-care slide). Plan item 2.1 is resolved — and better
than the plan asked, since the plan only asked to de-duplicate the slides.

### F4. Focus and motion — DONE
`focus-visible:ring-*` is applied consistently on footer/header links and CTAs.
`prefers-reduced-motion` is respected (`motion-reduce:` utilities and guards in
`styles/animations.scss`).
